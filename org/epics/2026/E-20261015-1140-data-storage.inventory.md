## How the server gets data today

1. Every 15 minutes, `alto-stance-sync.timer` runs
   `backend/scripts/stance_sync_trigger.py:48-67`. It fetches `origin main`
   and checks out only `data/alto_data/stances`. Its HEAD stays behind
   origin, so stance files show as modified on the server.
   `docs/ocean/setup.md:341` says never to run a plain `git pull` there.
2. A manual Sync Data button calls `POST /api/profile/sync-data`, which runs
   `sync_all_repos` (`server_side_data_pull_sync/sync.py:74,277`). It
   discards every local change in news_server and alto (`sync.py:228`), then
   fast-forwards. Only `alto_workspace` is committed and pushed from the
   server.

So intake, the watchlist price history and the benchmark stances reach the
server only when someone presses Sync Data.

**What story 4 keeps in git:** the server needs only
`alto_data/stances`, `alto_data/intake` (as a display summary),
`strategy/price_watchlist/price`, optionally `benchmark_deepseek/stances`,
and `system/users.json`. Everything else in news_server's 385k tracked
files is Mac-only.

## Stores written on both machines (lost-write risk)

- `system/users.json`: Sync Data discards the server's changes, so a user
  created on the server is lost (inferred from the discard logic).
- `alto/data/metadata/{price_watchlist,active_watchlist,custom_selected_watchlist}.csv`:
  Sync Data discards cockpit watchlist edits made on the server. Each machine
  also rebuilds the list from its own workspaces (`union/sources.py:46`), so
  the two lists can disagree. The Mac copies are uncommitted in git status
  today.
- `strategy/price_watchlist/versions/`, `scheduler/*` and
  `system/data_sync_status.json`: each machine writes its own copy, and the
  server's copy is wiped on sync.

## What this changes in the epic

  more urgent than it looked: blob_storage and raw_reports are 12.7 GB of
  raw sources whose only copy outside this disk is git.

  Story 4's first step, stopping scratch from entering git, is the cheapest
  win.

  and lose server-side writes on sync (users, watchlists).
