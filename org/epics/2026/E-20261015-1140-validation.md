## Goal

Every stage has checks over stored state, per company, that give one
structured verdict (check id, subject, pass / fail / unavailable / waived, a
fixed reason, evidence). Each check is proved on real frozen cases before it
is trusted, and releases are compared live vs candidate on a frozen snapshot.
QA, ops and dev use these instead of writing their own scripts.

## Stories

1. Freeze a company's stored state into a case (manifest, hashes; read-only on live) — next
2. First cases: ARSSBL, CHANDAN, one healthy company; then the other 8 of I-20261015-1058 — next
3. Expected verdicts per case — idea
4. Case runner: every check over every case vs expected verdicts — idea
5. Verdict contract, check catalogue and one command (`python -m backend.validation run`) — idea
6. Stage invariants (ingestion, index, intake, quarterly completeness, stance chain, proposal, execution), each proved on cases — idea
7. Chain completeness with explicit states: analysed, pending, blocked (reason), unavailable at source (evidence, recheck date) — idea
8. Release runner: live vs candidate on a golden snapshot, stage-by-stage changes; LLM replay / qwen tiers — idea (needs T-20261015-0321-checkout-data-root)
9. Ship refuses a release without a passing report — idea

## Open questions

- Where frozen cases are stored: their own small git repo (recommended) or `alto_runs/`.
- Whether validation becomes its own vertical and role, once authoring checks is ongoing work.

**Libraries** (decided in session, 2026-10-15): keep pydantic (verdict
model), pytest (check self-tests), duckdb (cross-store queries); add Dagster
asset checks (orchestration epic) and later deepdiff for the release diff.
Not adopted: Great Expectations, Soda, pandera (table-shaped checks; ours
are chain and point-in-time invariants), DVC for now, vcrpy, LLM-eval
frameworks (Research's area).

**Experiment and backtest validity gaps** found by the research audit,
input for stories 6 and 8 (no task exists for them):

- Stance records carry no model name or config provenance, so a release
  diff cannot tell which model wrote a stance.
- No guard against training-cutoff contamination in backtests.
- Benchmark cohorts were selected by outcome.
- `backend/e2e/run.py:456`: `--stance-output-dir` defaults to `DATA_ROOT`,
  so an experiment run without it writes production stances.
- `extract_signals` rewrites production logs; `stance/filter_cache.py:17`
  `FilterCache` is shared across roots.
- No backtest vs live parity check. Slippage is 5 bps in
  `backtest/replay.py:84` and `sweep.py:437`, 10 bps in
  `backtest/benchmark/cli.py:44`. No liquidity model.
- No promotion gate: Kimi became production in `ab783d7` without one.
- `sig_start = "2026-25-01"` (an invalid date) is hard-coded in
  `backtest/sweep.py:806` and `backtest/scripts/compare_tiebreak_modes.py:348`.
