## Goal

A **lane** is a complete definition of the product: which companies, which
steps, which models and prompts, which scoring and ranking, which trading
rules, at which commit. Live is one lane. A shadow lane is any other lane, run
every night beside live on the same as-of inputs, in its own sandbox with a
paper book, never touching production. Every release and every lane writes the
same metrics, and one dashboard compares them over time. The owner promotes,
keeps or drops a lane from that evidence. Owner sessions 2026-10-16 (rethink:
many lanes, different universes, steps, LLM analysis and scoring).

Draft for the owner; not approved; no tasks.

## Capabilities

What a lane can differ in from live (any combination):

| # | Capability | Example |
|---|---|---|
| 1 | Code | a research commit, a branch |
| 2 | Universe | companies not in live, a subset, a sector |
| 3 | Models and prompts | DeepSeek instead of Kimi; a local 9B; a changed prompt |
| 4 | Steps | an extra LLM analysis (e.g. a management-quality pass); a step skipped |
| 5 | Scoring and ranking | a different stance score, ranking or target-weight method |
| 6 | Trading rules | rebalance frequency, position limits, slippage |
| 7 | Start point | reuse live's analyses and redo only the stance, or redo from extraction |

What every lane gets:

- **Its own sandbox** (checkout-data-root `mode: sandbox`): it can never write
  live stores or reach Dhan; trades go only to the paper broker.
- **Shared compute.** A step whose inputs, code and config are identical to
  another lane's (or live's) reuses that result, keyed by content, so a lane
  pays only for what it changes. A config change gives new keys; nothing is
  reused across different configs.
- **Provenance.** Every stance and order records lane, commit, model and
  config hash.
- **Completeness gate.** A lane day counts only if its chain covered every
  company with the same inputs live had; otherwise the day is a gap, never a
  score.
- **Metrics store.** Each lane-day and each release run writes one record:
  returns, drawdown, turnover, hit rate, stance agreement with live,
  coverage, LLM cost and time.
- **Dashboard.** Lanes and releases over time: equity curves, metrics table,
  per-company stance differences against live, cost per lane, gaps.
- **Scheduling.** Runs on the Mac after the production chain (00:30 to about
  05:00); production always first; a lane that cannot finish before the next
  production run stops and records a gap.
- **Budget.** Open question (A/B/C below).
- **Lifecycle.** registered → running → paused/stopped → promoted or retired.
  Promotion is the owner's D- decision and the promoted lane must still pass
  release validation.
