## What one release run does

1. **Sandbox.** A worktree at the candidate commit with
   `.alto_checkout.yaml` `mode: sandbox` (T-20261015-0321-checkout-data-root)
   and an empty data root. Nothing in it can resolve to production.
2. **Seed.** For each release-set company, load its case from
   `alto_testcases` (hash-verified), copy the stores as they were at the
   window start, and apply its declared edits. The random live company is
   fetched live into the same root; its seed is recorded.
3. **LLM.** The sandbox LLM config points every workflow and stance agent at
   the local 4B/9B endpoint. The endpoint down = the run fails; no cloud
   fallback.
4. **Clock.** For each day from the earliest window start to 2026-10-15: make
   the sources whose `publish_date` (after edits) is that day visible, then
   run the chain the way production does (the Dagster job once the chain
   wrap lands), then the trading tick.
5. **Checkpoints.** On each checkpoint day, run the checks named in the
   scenario's expected file and compare verdicts. A mismatch is recorded,
   not fatal, so one run shows every failure.
6. **Report.** One file per run: candidate commit, case hashes, LLM model,
   per checkpoint expected vs actual verdicts, general invariants for every
   company, and the paper book's orders and fills. Ship refuses a release
   without a passing report (story 9).

## Local broker

Found 2026-10-16 (read-only map of `backend/`):

- The broker is duck-typed; `DhanClient` (`executor/dhan_client.py:203`) is
  the only one able to place orders.
- One factory builds it: `execution/service.py:43` `_create_broker_client`.
  The trading loop reuses it (`api/services/trading_loop_service.py:133`,
  `:221`). `EXECUTION_BROKERS = ("dhan",)` (`executor/credentials.py:83`).
- The EMS calls `place_order`, `order_status`, `cancel_order`, `quote`,
  `tick_size`, `lot_size` (`execution/manager.py`). The reconciler calls
  `order_status` (`execution/reconcile.py:178`). The book refreshes holdings,
  positions and fills through `stores/book/ledger_sync.py:67`.
- No paper broker exists; the factory comment says a default was left out
  for safety.

Design:

- `executor/paper/` holds a `PaperBroker` with exactly the methods above.
  It fills against the sandbox's stored prices for the clock's day (close,
  plus the slippage of the research protocol), keeps its own holdings,
  funds and fills in the sandbox root, and rejects an order when there is
  no price for that day (FC11).
- `"paper"` is added to the brokers the factory accepts **only when the
  checkout is `mode: sandbox`**; in live mode it raises. A sandbox can never
  build `DhanClient`. The shadow lane reuses it.
- The human decision is part of the product. The runner approves every
  proposal through the same `RebalanceService.submit_decision` path, so the
  approval, intent book, EMS and reconciler all run.
