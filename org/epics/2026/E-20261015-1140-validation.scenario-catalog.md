# Release scenario catalog (draft for owner approval)

Owner session, 2026-10-16. Design for stories 1–3 and 8 of
E-20261015-1140-validation. Not a task; the owner creates tasks from it.

## Purpose

Every release runs the whole chain live (discovery → intake → workflows →
stance → trading to a local fake broker) on a fixed set of companies, each
chosen to prove one failure class, plus one random live company. The worst
failure is wrong-but-green, so every expectation is a verdict over stored
state, never an exit code or LLM text.

Owner decisions in this session:

- All scenarios run live every release on a local LLM (4B/9B). Output
  quality is not judged; structure and point-in-time correctness are.
- Inputs are frozen real cases plus declared edits, plus one random live
  company per release (seed recorded). No separate daily canary: the
  nightly Dagster chain (E-20261015-1140-orchestration-and-ops) covers
  production.
- Cases and scenarios live in their own repo,
  `workspace/alto_testcases` (answers this epic's open question).
- Window per case: start = min(2026-07-01, FY26 annual report
  `publish_date`), end = 2026-10-15 for every case.
- Bank metrics and monthly sales are legacy and are out of scope.

## Terms

| Term | What | Owner |
|---|---|---|
| Case | One real company's sources and stores frozen at an as-of, with manifest and hashes (story 1) | this epic |
| Scenario | A case + declared edits + checkpoints + expected verdicts | this design |
| Failure class | The one problem a scenario proves the product handles | this catalog |

## Failure classes

| ID | Class | Source of the state | Must hold |
|---|---|---|---|
| FC01 | Healthy, complete | real | each quarter analysed once, chain continuous, trades to target |
| FC02 | Missing quarter at source | real (ARSSBL) or `drop_document` | quarter Due/Missing with evidence; stance and proposal blocked |
| FC03 | Reporting period not extracted | real (CHANDAN, TAC, PNGSREVA) | fails at index/intake with a reason; nothing attached to a wrong quarter |
| FC04 | Same quarter from two sources | `duplicate_from_source` | one analysis per quarter (`backend/docs/30_quarter_identity.md`); earliest knowable publish date |
| FC05 | Corrupt or incomplete document | `corrupt_file` | extraction fails loudly; partial text never analysed as complete |
| FC06 | Late filing | `delay_arrival` | invisible before arrival; then a new quarter version and a new stance link; history not rewritten |
| FC07 | Late macro event | `delay_arrival` on a macro file | the AsOfLedger hides it before arrival; the next link uses it |
| FC08 | Broken chain needing repair | real (I-20261015-1058) | reconcilers find it; repair through owned commands; rerun passes |
| FC09 | Pre-feed-start gap | real (ABDL, EMUDHRA, FAIRCHEMOR, …) | bodies fetched or marked missing with evidence; never silently skipped |
| FC10 | Not initiated | real | state Not initiated; no stance, no trade |
| FC11 | Price gap on a trade day | `drop_price_day` | order refused with a reason; no fill at a stale price |
| FC12 | Corporate action (split/bonus) | to be decided | prices and positions adjusted; no false crash in the stance. Implementation unknown: investigate first |
| FCR | Random live company | live, seed recorded | general invariants only (below) |

General invariants (FCR and every scenario): every index entry has
`publish_date` and `reporting_period`; one analysis per quarter; no input
dated after the as-of; chain continuous over the window; orders match
target weights.

## Selection

- Candidates per class come from a read-only query over production stored
  state (index, quarter versions, intake failures, stance log).
- The pick, the query, its as-of and the reason are a cohort item
  `research/cohorts/C-…-release-scenarios` (immutable, hashed).
- Never selected by trading outcome.
- About one company per class. A real failure found by FCR may be frozen
  and promoted into a new scenario; the catalog grows from real failures.

## Contract

`scenario.yaml`:

```yaml
schema: scenario/v1
id: FC04-duplicate-quarter-XYZ
class: FC04
case: XYZ@2026-10-15
cohort: C-20261016-…-release-scenarios
window: {start: 2026-05-28, end: 2026-10-15}   # start copied from the case manifest
edits:
  - op: duplicate_from_source
    target: {doc: bse/2026-08-12_Q1FY27_results.pdf}
    as: {source: screener, publish_date: 2026-08-14}
```

Edit vocabulary (closed; an unknown op or a missing target raises):

| op | Params | Classes |
|---|---|---|
| `drop_document` | doc | FC02 |
| `duplicate_from_source` | doc, source, publish_date | FC04 |
| `corrupt_file` | doc, mode: truncate \| empty \| garbage | FC05 |
| `delay_arrival` | doc or macro file, arrival date | FC06, FC07 |
| `drop_price_day` | date | FC11 |
| FC12 op | after the investigation | FC12 |

Edits apply to the sandbox copy only; a case is never modified.

`timeline.yaml`: arrivals follow each file's `publish_date` after edits;
the timeline declares only checkpoints.

```yaml
checkpoints:
  - {day: 2026-08-13, expect: expected/2026-08-13.verdicts.yaml}
  - {day: 2026-08-15, expect: expected/2026-08-15.verdicts.yaml}
  - {day: 2026-10-15, expect: expected/2026-10-15.verdicts.yaml}
```

`expected/<day>.verdicts.yaml` uses the verdict contract of
T-20261016-1718-completeness-check:

```yaml
- {check: quarterly.one_analysis_per_quarter, subject: XYZ/Q1FY27, verdict: pass}
- {check: stance.chain_continuous, subject: XYZ, verdict: pass}
```

A scenario naming a check absent from the check catalogue (story 5) fails
catalog validation.

Case manifest: symbol; window start with its evidence (the FY26 annual
report document and `publish_date`); alto and news_server commits frozen
from; sha256 per file. A missing FY26 annual `publish_date` raises, except
FC10, whose start is 2026-07-01 by design.
