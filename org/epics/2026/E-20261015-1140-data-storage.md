## Goal

Each store is classed (product state, raw source, queue, run history,
scratch, experiment, company record) and kept accordingly: git tracks only
what the server reads, raw sources live outside git with a tested backup,
run history is one file per run with retention, scratch expires.
Measured 2026-10-15: `news_server` 401k files / 28 GB, 385k tracked, `.git`
8 GB; e2e writes ~4–5k files per run; 18 stale worktrees hold 70k files.

## Stories

1. Inventory: every store's kind, files, size, weekly growth, readers, whether the server needs it, git-tracked, proposed retention — next
2. Retention policy as a standing owner decision, from the inventory — idea
3. Backup independent of git, proved by a restore, before anything is untracked or deleted — idea
4. The data repo tracks only what the server reads — idea
5. Raw sources (blob_storage, raw_reports) content-addressed outside git — idea
6. Run history one file per run, then Dagster's event log; old runs compacted — idea (spike question B7)
7. Scratch expires; stale worktrees removed from an owner-approved list — idea
8. Finished experiments packed into `alto_runs/<id>/` — idea

## Open questions

- Object storage for raw sources: local disk with off-machine backup, or a bucket.
