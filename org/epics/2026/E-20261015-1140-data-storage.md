## Goal

Each store is classed (product state, raw source, queue, run history,
scratch, experiment, company record) and kept accordingly: git tracks only
what the server reads, raw sources live outside git with a tested backup,
run history is one file per run with retention, scratch expires.
Measured 2026-10-15: `news_server` 401k files / 28 GB, 385k tracked, `.git`
8 GB; e2e writes ~4–5k files per run; 18 stale worktrees hold 70k files.

## Stories

1. Inventory: every store's kind, files, size, weekly growth, readers, whether the server needs it, git-tracked, proposed retention — done (`E-20261015-1140-data-storage.inventory.md`)
2. Retention policy as a standing owner decision, from the inventory — idea
3. Backup independent of git, proved by a restore, before anything is untracked or deleted — idea
4. The data repo tracks only what the server reads — idea
5. Raw sources (blob_storage, raw_reports) content-addressed outside git — idea
6. Run history one file per run, then Dagster's event log; old runs compacted — idea (spike question B7)
7. Scratch expires; stale worktrees removed from an owner-approved list — idea
8. Finished experiments packed into `alto_runs/<id>/` — idea
9. Stores written on both machines (users.json, watchlist CSVs, price_watchlist versions) get one owner, so Sync Data stops discarding server writes — idea
10. Dead stores (triggers, top-level book/execution/orders/rebalance, unused constants) untracked after backup — idea

## Open questions

- Object storage for raw sources: local disk with off-machine backup, or a bucket.
- Credential files tracked in news_server git (`alto_data/system/{dhan,kite}_credentials.json` and a `.bak`, `macro/sources/sovrenn/data/.token`): rotate, untrack, rewrite history? Owner's call; no agent touches them.
- Is `alto_data/workspace/scienceamit1/` on the Mac product state or a test copy? (356 tracked files despite the ignore rule.)
- Intake reaches the server only on a manual Sync Data; should the cockpit's intake view read a synced summary instead?

## Findings

2026-10-15, read-only; full table, sync paths and worktree list in
`E-20261015-1140-data-storage.inventory.md`, counts reproducible with
`E-20261015-1140-data-storage.measure.py`.

- The server needs from news_server only `alto_data/stances` (15-min
  checkout, `stance_sync_trigger.py:48-67`), `alto_data/intake` (cockpit
  display), `strategy/price_watchlist/price`, optionally
  `benchmark_deepseek/stances`, and `system/users.json`. The other ~380k
  tracked files are Mac-only.
- Largest git weight is scratch: `data/temp` 2.77 GB of 7.61 GiB packs.
- Raw sources (blob_storage 6.66 GB, raw_reports 6.03 GB) have no copy off
  this disk except git: story 3 comes before any untracking.
- Fastest growth: blob_storage (+102k files in 30 days), intake (+27.7k),
  e2e logs (+41.7k in 7 days), workflow runs (+11k in 7 days).
