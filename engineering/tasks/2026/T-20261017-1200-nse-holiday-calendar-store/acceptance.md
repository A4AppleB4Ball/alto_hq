# Acceptance: NSE holiday calendar store

1. **One path.** `backend/config/paths.py` defines `NSE_HOLIDAYS_DIR`. A test (AST) shows no module outside `backend/lib/market_calendar/` builds a holiday file path, and `PAPER_HOLIDAYS_FILE` no longer exists (`grep -rn PAPER_HOLIDAYS_FILE backend` is empty).
2. **No NSE call from a reader.** A test (AST or grep) shows `backend.connectors.nse` is imported only by the market-calendar fetch module (and other existing non-holiday NSE users, listed by exact file name). It also shows that `nse_trading_holidays` never calls the fetch. The test patches `NSE` to raise, calls every reader with a seeded store, and the reader returns the stored dates.
3. **Missing year raises.** With an empty store, `nse_trading_holidays` for 2026 raises an error whose message names the full `<NSE_HOLIDAYS_DIR>/2026.json` path and the year. A span that crosses into a missing year (for example 2026-12-20..2027-01-05 with only 2026 stored) raises naming 2027. There is no fallback to weekends-only or to another year.
4. **Readers wired.** Each reader gets the calendar from the store, and a test covers each one: `require_current` on both sandbox paths (`broker_factory/prices._shared_cache_window`, `broker_factory/daily_series`), the paper broker in `broker_factory/build.py`, `price_watchlist` cli/capture and `trading_loop_service`. For each reader, a missing year raises the error from check 3, and a seeded store gives the same result as before.
5. **Writer.** `python -m backend.lib.market_calendar.cli fetch`, with the NSE response patched to a fixture, writes `<year>.json` with sorted ISO CM dates, `fetched_at` and `source`. Running it a second time with the same fixture leaves the bytes unchanged. A changed fixture overwrites the file and logs the diff. An empty CM list raises and writes nothing. In a sandbox checkout the CLI raises before any network call (the test patches `NSE` to fail if called).
6. **Scheduled.** `backend/config/pipeline_scheduler.yaml` has an `nse_holiday_calendar` job whose command is the CLI from check 5. The job is daily, scheduled before `refresh_price_cache`, in `collision_group: data_pipelines`. The scheduler's existing config loader parses the file (test or `python -c` load).
7. **Sandbox makes no network call.** In a sandbox worktree with a seeded store, the T-2336 sandbox price tests run with sockets blocked (a test patches `socket.socket.connect` to raise) and pass. This closes T-2336 check 11 (holiday half).
8. **Suite.** No new failure against a sandbox-worktree base (`comm -23 new base` is empty). `stores/tests/test_boundaries.py` passes. The entry points import: main_cockpit, app_factory, e2e.lanes, harness, price_watchlist.cli, trading_loop_service, asof and market_calendar.cli.
9. No live fetch, no LLM run and no network call during dev or QA. The first live fetch is the owner's call.
