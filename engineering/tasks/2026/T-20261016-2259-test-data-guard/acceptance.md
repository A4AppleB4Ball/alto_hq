# Acceptance: test-data-guard (approved)

Starts after checkout-data-root merges.

1. **Mode.** `.alto_checkout.yaml` accepts `mode: test`; `backend.config.paths` then takes every root from a per-run temp dir, removed at session end. A test in `backend/config/tests/` shows `STANCES_DIR` is under the temp root.
2. **One guard, attributed to the process that writes.** In test mode, every write-class operation by the test process or any child it starts (open for write/append/create, mkdir, rename/replace, remove/rmdir/unlink, copy/move, and DuckDB connections) on a path that resolves under the live root is refused at the call with `LiveRootAccessError` naming the operation and path. Reads stay allowed. The guard is installed in `load_checkout` for every non-live checkout (sandbox declaration as well as test mode), not only inside a pytest session, so a pytest run from outside `backend/`, a plain script, or a child that imports `backend.config.paths` is guarded too; in live mode it is never installed. Tests show: a script run from a directory outside `backend/` under a sandbox declaration, and pytest run with `--noconftest`, both refuse a write under the live root (reproducing how the ZZNOSUCH debris happened), and live mode installs nothing. Tests in `backend/config/tests/`, each failing before and passing after, show: a direct file write, a store write (`CompanyStore(live_root/...).append_stance`), a rename, a DuckDB connect, and a child process write are all refused; a write under the per-run temp root and a read of the live root are allowed; a symlink under the temp root pointing into the live root is refused (resolved path).
3. **Nothing reaches production, proven without polluting it.** No check writes to the live root. (a) With a modification marker on the live root, `python -m pytest backend/api/services/tests/test_rebalance_price_action_cooldown.py -q` at head leaves nothing under the live root newer than the marker, excluding `workspace/*/book/*` and `scheduler/*` (written by the live server). (b) The tests of check 2 run inside a temp copy so the real live root is untouched. (c) The earlier whole-tree snapshot watcher (`live_root_watch.py`) and its path exclusions are removed: a live server writing during a run can no longer fail the suite, and the suite no longer walks the live tree. The earlier base-half (reproducing pollution on base against production) is removed by the owner: production is never polluted on purpose.
4. **Full suite.** Run the whole backend suite at head under a sandbox declaration and under `mode: test`, with the marker: no file under the live data root is created or modified by tests, and the run no longer ends in a watcher error while the live server writes. Failures vs base: no new ones (`comm -23`).
5. **Repo checks.** Boundary test, entry-point imports.
