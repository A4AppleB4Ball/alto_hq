# Acceptance: price-reads-asof-and-start-coverage (approved)

1. **Non-trading as_of.** The last-trading-day rule uses a stored multi-year NSE holiday list kept in `NSE_BSE_Data` (a path constant in `backend/config/paths.py`, beside the Dhan cache roots), never a network call at read time. A command in the owning package writes the list; the data file itself is populated by the owner, not by the dev. A test: cache ends on a Friday; a non-live read with a Saturday or holiday `end` returns the series through Friday, using a temp holiday list; a date after the last trading day the cache could know raises `PriceCacheMissError`. A read with the network blocked, a December cache end and a January `end` works across the year boundary when the list covers both years, and raises a named error naming the missing year when it does not. Fails on base, passes after.
2. **Start coverage.** A test: cache starts 2026-01-01, read with `start=2024-01-01` raises `PriceCacheMissError` naming the first cached date, unless the symbol's listing date is after `start` as recorded by an existing store (state which). Fails on base, passes after.
3. **Live unchanged.** Existing live-path tests pass unedited.
4. **Pilot read.** (cache ends 2026-10-13: a Saturday 2026-10-17 end raises because Wed-Fri are trading days the cache lacks; a 2026-10-14 end raises.) A 20MICRONS read in a credential-less sandbox for a Saturday as_of after 2026-10-13 behaves per check 1.
5. **Start on a non-trading day.** A `start` falling on a weekend or holiday before the first cached trading day does not raise (a cache built from that same start re-reads cleanly); a start before the first trading day the cache holds, with trading days missing, raises.
6. **Repo checks.** Boundary test, entry-point imports, full suite vs base with `comm -23`.
